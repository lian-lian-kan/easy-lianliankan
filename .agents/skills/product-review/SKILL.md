# 连连看产品设计审查

对任何 UI/交互改动，按下面的清单顺序过一遍。权威事实源是 `docs/product-map.md`
（层级模型 L0–L4、页面清单、闭环清单、断言映射）——**先读它再动手**；改动落地后
必须同步更新该文档，文档、代码、断言三者一致才算闭环。

## 1. 层级归属（先问放哪层，再动手）

- L1 棋盘是唯一玩法主场；L2 一级导航页 7 键封顶（390px 物理极限）。
- 新内容优先级：导航页 > 二级页（L2.5：数据/任务/成就/攀登树范式）> 弹窗。
- 陈列型内容（列表/收集/进度）做成页面；强上下文操作（暂停/迁移/工坊）留弹窗；
  只反馈不做导航的走浮层（横幅/toast）。
- 二级页入口三件套：首页快捷区、设置面板、相关一级页的入口卡——至少给两条路。

## 2. 入口/出口配对（每个动机有去处，每个去处有归途）

- 新增任何入口时同步回答：用户到达目标页后**怎么回来**？回棋盘（‹ 返回）还是回首页（⏸→🌸）？
- 跨页跳转用 `PAGE_ROUTER.show_page`（页面互跳）；离开页面语境用 `close_page`（回棋盘）。
- 动机型按钮要带目的地文案（先例：任务页「🗺️ 去闯关」「▶ 去开局」），不做裸「前往」。

## 3. 闭环核对（对照 product-map.md 的闭环清单）

每条产品闭环（玩法/签到/任务/成就/收集/登高/回家/迁移）被本次改动触碰时：
- 走一遍完整动线：入口 → 中间页 → 完成动作 → 回到收益页领取/查看。
- 「前往」类闭环的出口必须真的减少步骤（例如任务页直达玩法大厅，而不是让用户自己找导航）。
- 收益就地刷新用 `PAGE_ROUTER.rebuild_page`（未开页早退，安全）。

## 4. 视觉与文案一致性

- 所有按钮走品牌样式：主按钮 `style_dialog_buttons`（实心玫瑰），次级 `style_secondary_button`
  （白卡粉字）；一个面板只留一个主按钮。禁止裸 `Button.new()` 上屏（玩法大厅白卡范式）。
- 文案走甜系少女向（可爱/治愈/宠溺/带 emoji），禁电竞风；数字与奖励信息必须保留。
- 新文案字符必须重跑 `python3 godot/tools/subset_fonts.py`（漏跑 = 线上空白字）。

## 5. 断言映射（改动不算完，锁住才算完）

- 页面开关/内容渲染 → `page_probe`；弹窗与品牌锁 → `panels_probe`；首页 → `start_screen_probe`。
- 新增页面至少锁四件事：能打开（current_page 正确）、内容非空、暂停语义成立、关闭回棋盘恢复。
- `docs/product-map.md` 的闭环清单行更新后，同轮补齐对应探针断言。

## 6. 已知雷区（重复踩过的坑）

- 探针模拟真实启动须 add_child **之后**再赋 `current_scene`（setter 拒绝树外节点）。
- 本地共享 user:// 存档会让支付类断言漂移——本地红先和干净基线 diff 失败集，
  CI 干净环境才是权威。
- IAB 线上验证：清 SW + caches + 带参强刷才见新包；面板刚切换 ~1s 内的点击会被吞
  （间隔 ≥2.5s）；按钮坐标以 headless 布局 dump 为准，不信截图目测。
